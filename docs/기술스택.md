# 퇴사각 펫 — 개발 언어 · 기술 스택 (안)

## 결정 요약 (2026-11-14)
- **데스크톱 앱: Electron** (웹 기술로 데스크톱 앱 `.exe`, `.dmg` 를 만드는 도구, 앱 용량 약 100MB 안팎)
  - 용량을 줄이려고 **Wails(약 10MB 안팎)** 도 고민했지만, Windows · macOS 등 서로 다른 OS 에서 **같은 결과가 안정적으로 나오게 하려면 Electron 이 낫다**고 판단함
  - **Electron + TypeScript** 로 앱의 프론트(화면)와 백엔드(로직)를 모두 작성
- **DB: Supabase** (PostgreSQL + 로그인 + 파일 저장을 제공하는 서비스)

## 결론
**TypeScript 하나로 통일 — Electron + React + Supabase**

| 영역 | 선택 |
| --- | --- |
| 언어 | **TypeScript** (앱 화면·로직, 관리자 웹 전부) |
| 데스크톱 앱 | **Electron** (+ electron-vite 템플릿) |
| 화면(캘린더·대시보드·질문 UI) | React |
| 펫 렌더링·애니메이션 | 스프라이트 시트 + Canvas (애니메이션이 많아지면 PixiJS) |
| DB · 로그인 · 파일 저장 | **Supabase** (PostgreSQL, 서울 리전) + `@supabase/supabase-js` — 스키마는 [schema.sql](schema.sql) |
| 관리자 웹 | React + TypeScript (Supabase 에 연결) |
| 그래프 | Recharts 또는 Chart.js |
| 배포 | electron-builder (macOS `.dmg` / Windows `.exe`) |

## 전제
기획에 나온 기능들이 **바탕화면 위에 떠 있는 펫**을 가정함
- 화면 위에서 돌아다니고, 클릭·드래그·쓰다듬기
- "사용자 인터랙션이 없을 때 = 바쁘다고 인식" → PC 입력 상태를 읽어야 함
- 퇴근 독촉, 업무 방해, 오후 4시 질문 쪽지 → 다른 프로그램 쓰는 중에도 보여야 함

→ 웹/모바일 앱으로는 불가능, **데스크톱 앱**이어야 함. (모바일이 목표라면 이 문서 다시 검토)

**지원 대상 OS: macOS + Windows 10 + Windows 11 전부** (회사 PC 에 Windows 10 이 아직 많음)

## 왜 Electron + TypeScript 인가

| 기획 기능 | Electron 에서 구현 방법 |
| --- | --- |
| 바탕화면 위 투명한 펫 | `BrowserWindow({ transparent: true, frame: false, alwaysOnTop: true })` |
| 펫 없는 영역은 클릭 통과 | `setIgnoreMouseEvents(true, { forward: true })` |
| "바쁨" 판정 | **`powerMonitor.getSystemIdleTime()` 기본 내장** — 별도 라이브러리 없이 마지막 입력 후 몇 초 지났는지 확인 |
| 잠금/절전 → 퇴근·휴식 상태 | `powerMonitor` 의 `lock-screen`, `suspend` 이벤트 |
| 오후 4시 질문 알림 | `Notification` + 펫 머리 위 쪽지 |
| 캘린더·대시보드·설정 | 별도 창에서 React — 웹 UI 라이브러리를 그대로 사용 |
| 트레이 아이콘 (펫 숨기기, 종료) | `Tray` 기본 내장 |

- Chromium(크롬 엔진)을 앱에 통째로 넣어 가는 구조라 **OS 버전과 상관없이 같은 결과**가 나옴
- 한 언어(TypeScript)로 펫·화면·점수 계산·관리자 웹 전부 → 팀원 누구나 어느 부분이든 수정 가능
- 자료·예제가 가장 많음 (데스크톱 펫 오픈소스 예제 다수)
- 단점: 앱 용량 큼(100MB 안팎), 메모리 사용량 상대적으로 큼 → MVP 단계에선 문제 안 됨

## 비교한 다른 선택지

| 후보 | 장점 | 탈락 이유 |
| --- | --- | --- |
| **Wails v3 (Go + TS)** | 백엔드를 Go 로 작성 가능, 앱 용량 10MB 안팎·메모리 적음, Go 함수가 TS 로 자동 바인딩 | 투명 창이 문서상 Windows 11 이상만 지원 → **Windows 10 지원 불확실**. 클릭 통과·유휴시간 감지를 직접 구현해야 함. 자세한 내용은 [아래 검토 기록](#go--wails-검토-기록-2026-11-14) |
| **Tauri (Rust + TS)** | 앱 용량·메모리 훨씬 작음 (항상 켜두는 앱에 유리) | 유휴시간·창 제어 등 네이티브 기능에 Rust 코드 필요, 투명 창·클릭 통과가 OS별로 덜 안정적. **출시 단계에서 용량이 문제되면 전환 고려** — 화면 코드(React)는 그대로 재사용 가능 |
| Unity / Godot (C# / GDScript) | 픽셀 애니메이션·연출에 가장 강함 | 캘린더·대시보드·입력 폼 같은 일반 UI 만들기 번거로움, 앱 무거움 |
| Python (PyQt 등) | 배우기 쉬움 | 배포 파일 만들기 까다롭고, 애니메이션·UI 품질 확보 어려움 |
| Swift / C# 네이티브 | 가볍고 OS 기능 완벽 | macOS·Windows 를 따로 만들어야 함 |

## Go / Wails 검토 기록 (2026-11-14)

### 배경
개발자가 TypeScript 보다 **Go 에 더 익숙**해서, 백엔드를 Go 로 할 수 있는지 검토함.

### 검토 1 — Electron 앱 안의 백엔드(`main/`)만 Go 로 바꾸기
- Electron 의 `main/` 은 Node.js 에서만 돌아감. 투명 창·트레이·알림·`powerMonitor` 등이 전부 Node.js 용 API
- Go 로 하려면 앱 안에 Go 프로그램을 따로 넣고 Electron 과 통신시켜야 함 (사이드카 방식)
  - 프로그램 2개를 OS 별로 같이 빌드·배포해야 함
  - 둘 사이 통신 코드가 추가로 필요함
  - 창 제어는 결국 TS 로 짜야 해서 언어 2개를 관리하게 됨
- **결론: 얻는 것보다 복잡도가 커서 제외**

### 검토 2 — Wails v3 (Go 로 만드는 데스크톱 앱)
**Wails 란?** "Go 버전 Electron". 화면은 웹 기술(React + TS), 로직은 Go 로 짜는 데스크톱 앱 도구.

| | Electron | Wails |
| --- | --- | --- |
| 웹 엔진 | Chromium 을 **앱에 포함** | OS 웹뷰를 **빌려 씀** (macOS: WKWebView, Windows: WebView2) |
| 백엔드 언어 | TypeScript (Node.js) | Go |
| 화면 ↔ 로직 | IPC + preload 를 직접 작성 | Go 함수가 TS 로 자동 바인딩 |
| 앱 크기 | 100MB 안팎 | 10MB 안팎 |
| OS 기능 | 대부분 기본 제공 | 일부만 제공, 나머지는 OS API 를 직접 호출 |
| 화면 일관성 | 모든 OS 에서 같은 크롬이라 동일 | macOS(WebKit) 와 Windows(Chromium) 가 조금 다를 수 있음 |

- 2026-10-26 v3.0.0 정식 출시 (2026-11-01 v3.1.0) → 버전 안정성은 문제 없음

**펫 핵심 기능별 확인 결과**

| 기능 | 무엇인지 | Electron | Wails v3 |
| --- | --- | --- | --- |
| 투명·테두리 없는·항상 위 창 | 바탕화면 위에 펫만 보이게 | 기본 제공 | 지원. 단 **Windows 투명 배경은 문서상 Windows 11 이상** |
| 클릭 통과 | 펫 주변 빈 곳을 누르면 아래 프로그램이 클릭되게 | `setIgnoreMouseEvents(true, { forward: true })` 한 줄 | `IgnoreMouseEvents` / `SetIgnoreMouseEvents` 있으나 전부 통과 or 전부 받기. 펫 위에서만 받으려면 Go 에서 마우스 위치를 계속 확인해 직접 토글해야 함. macOS 동작 확인 필요 |
| 유휴시간 감지 | 마지막 키보드·마우스 입력 후 몇 초 지났는지 ("바쁨" 판정) | `powerMonitor.getSystemIdleTime()` 한 줄 | 없음. OS 별로 직접 구현 (Windows: `GetLastInputInfo`, macOS: `CGEventSourceSecondsSinceLastEventType` + cgo) |
| 트레이 아이콘 | 펫 숨기기·종료 메뉴 | 기본 제공 | 지원 |

### 결정: Electron + TypeScript
- 지원 대상 OS 가 macOS + Windows 10 + Windows 11 전부
- Wails 는 OS 기능을 빌려 쓰는 구조라 오래된 OS 일수록 안 되는 게 생김. Electron 은 필요한 걸 앱에 다 넣어 가서 OS 와 상관없이 같은 결과
- 펫의 핵심 기능(투명 창, 클릭 통과, 유휴시간)이 OS 버전에 따라 될지 말지 걱정할 필요가 없는 쪽을 선택

### Go 는 나중에 필요하면
- 지금은 Supabase 가 서버 역할을 해서 **별도 서버 없음**
- 관리자 기능이 복잡해지면(복잡한 통계 배치, 외부 시스템 연동 등) **관리자 전용 API 서버를 Go 로** 추가 검토
- 그 경우 앱·관리자 웹(TS)과 서버(Go)의 데이터 타입을 따로 정의하게 되므로 OpenAPI 등으로 타입 자동 생성 검토

### 다시 검토할 조건
- Windows 10 지원을 중단하게 될 때
- 출시 후 앱 용량·메모리 사용량이 실제 문제가 될 때
→ Wails(Go) 또는 Tauri(Rust) 로 전환 검토. 화면(React) 코드는 그대로 재사용 가능

## DB: Supabase

### 처음 계획(로컬 SQLite)에서 바꾼 이유
처음엔 기록이 PC 밖으로 나가지 않도록 각자 PC 의 SQLite 에만 저장하려 했음. 하지만 그러면 **서버가 없어서 관리자가 아무것도 할 수 없음.** 관리자에게 아래 기능이 모두 필요해서 데이터 원본을 서버(Supabase)에 두기로 함.

| 관리자 기능 | 내용 |
| --- | --- |
| 콘텐츠 관리 | 질문 문구, 펫 대사, 펫 종류, 이벤트를 **앱 업데이트 없이** 추가·수정 |
| 사용 통계 | 사용자 수, 질문별 응답률, 평균 퇴사각 등 |
| 사용자 계정 관리 | 가입자 목록, 계정 정지·삭제, 문의 대응 |
| 개인 기록 열람·수정 | 특정 사용자의 답변, 하루 기록, 점수, 펫 데이터 확인·수정 |

### 왜 Supabase 인가
직접 서버를 만들면 해야 할 일을 Supabase 가 제공함 → MVP 를 빠르게 만들 수 있음

| 필요한 것 | Supabase |
| --- | --- |
| DB | PostgreSQL 제공 (운영·백업 포함) |
| 로그인·회원가입 | Auth 제공 (이메일, 구글, 카카오 등) |
| 데이터 읽기/쓰기 API | 테이블을 만들면 자동 생성 |
| "내 기록은 나만" 권한 | DB 규칙(RLS)으로 설정 |
| 스프라이트 등 파일 저장 | Storage 제공 |

- [schema.sql](schema.sql) 은 처음부터 모든 테이블에 `user_id` 를 둬서 **구조를 거의 그대로** PostgreSQL 로 옮길 수 있음 (SQLite 문법 → PostgreSQL 문법 변환은 필요)
- DB 가 일반 PostgreSQL 이라 나중에 다른 곳으로 옮기거나 직접 설치(셀프 호스팅)도 가능

### 구조
```
[사용자 PC]                            [Supabase (서울 리전)]
Electron 펫 앱 (TS)   ── 로그인 ──→      Auth
 - 펫, 알림, 유휴시간    ── 내 기록 ──→    PostgreSQL (RLS: 자기 데이터만)
 - 화면 (React)       ←─ 콘텐츠 ──      Storage (스프라이트 등)
                                            ↑
[관리자 웹 (React + TS)] ── 관리자 전용 DB 함수 ──┘
                          (권한 확인 → 감사 로그 기록 → 데이터 반환)
```

### 관리자 접근 방식 — "길목"을 반드시 거치게
- 관리자는 모든 사용자 데이터를 볼 수 있어야 하지만, 모든 권한을 가진 `service_role` 키는 **관리자 웹(브라우저)에 절대 넣지 않음** (브라우저 코드는 누구나 열어볼 수 있음)
- 관리자는 테이블을 직접 읽지 않고, **관리자 전용 DB 함수**(`security definer`)로만 조회·수정
  - 함수 안에서: 관리자인지 확인 → **감사 로그(누가·언제·누구의 기록을 봤는지) 기록** → 데이터 반환
- 만능 키가 필요한 작업은 Supabase Edge Functions(TS) 에서 처리
- 관리자 기능이 복잡해지면 Go 서버로 이 길목을 옮기는 것 검토

### 개인정보 주의사항
퇴사 충동·스트레스 원인 같은 **민감한 기록이 서버에 저장되고 관리자가 열람할 수 있게 됨** → 사용자 신뢰·법적 책임 관리 필요
1. **서울 리전**으로 프로젝트 생성 (나중에 바꾸기 어려움)
2. **가입 시 동의**: 서버 저장과 운영자 열람 가능성을 개인정보 처리방침에 명시하고 동의받기. 출시 전 개인정보보호법 관련 검토
3. **감사 로그**: 관리자 열람·수정 기록 남기기
4. **권한 분리**: 콘텐츠 담당자는 콘텐츠만, 지정된 담당자만 개인 기록 열람
5. **암호화**: HTTPS 통신, 민감한 항목은 암호화해서 저장
6. **회사 PC 문제**: 회사 방화벽이 서버 접속을 막을 수 있고, "회사 PC 에서 퇴사 기록이 밖으로 나간다"는 점을 사용자가 꺼릴 수 있음 → 기획에서 같이 고민

### 오프라인일 때
- MVP: 오프라인이면 기록 저장 불가 (펫 애니메이션·알림은 정상 동작)
- 필요해지면: PC 에 임시 저장(SQLite)했다가 연결되면 서버로 전송

### 요금
- 무료 플랜은 일정 기간 사용이 없으면 프로젝트가 일시 정지됨 → 실제 서비스는 유료 플랜 필요 (가입 시 금액 확인)

## 폴더 구조 (예시)
```
app/
├─ main/            # Electron 메인: 창 관리, 유휴시간 감지, 알림, 스케줄러(16:00 질문)
│  ├─ api/          # Supabase 클라이언트, 로그인, 기록 저장·조회, 콘텐츠 받아오기
│  ├─ scoring/      # 정규화, 퇴사각 지수 계산, dirty 재계산
│  └─ pet/          # 상태 우선순위 엔진
├─ renderer/
│  ├─ pet/          # 투명 창: 스프라이트 애니메이션, 말풍선, 쪽지
│  └─ dashboard/    # 캘린더, 일별 히스토리, 그래프, 설정
└─ assets/sprites/  # 캐릭터별 스프라이트 시트 (pet_species.asset_key)
admin/              # 관리자 웹 (React + TS): 콘텐츠·통계·계정·기록 관리
supabase/
├─ migrations/      # 테이블, RLS 규칙, 관리자 전용 DB 함수
└─ seed.sql         # 지표·질문·대사 초기 데이터
```

## 다음 단계
