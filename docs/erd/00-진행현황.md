# ERD 진행 현황

> 기획 기준: [기획정리.md](../기획정리.md) · 임시 결정: [기획정리_추가정리필요요소.md](../기획정리_추가정리필요요소.md)
> 진행 방식: **테이블 1개씩** 만들고, 예시 데이터로 설명 → 이해 확인 → 다음 테이블
> 모두 끝나면 [ERD.md](ERD.md) 에 전체 관계도로 합침
> 기초: [Supabase 구조](00-supabase-구조.md)

## 모든 테이블 공통 규칙

| 규칙 | 이유 |
| --- | --- |
| 기록 테이블에는 `user_id` (= `auth.users` 의 id) | 누구 것인지 + RLS ([Supabase 구조](00-supabase-구조.md)) |
| `id` 는 uuid | 겹치지 않는 번호 |
| `created_at`, 필요하면 `updated_at` | 언제 만들고 고쳤는지 |

> 데이터 저장 방식: **Supabase 만 사용** (오프라인 미지원) → [C-6](../기획정리_추가정리필요요소.md)

## 순서

중심 테이블부터 바깥쪽으로 진행함

| 순서 | 테이블 | 한 줄 설명 | 상태 |
| --- | --- | --- | --- |
| 0 | [Supabase 구조](00-supabase-구조.md) | 기초: auth / public 구역, RLS, 왜 Supabase 인가 | 🔄 이해 중 |
| 1 | [users](01-users.md) | 사용자. **`auth.users` 를 그대로 씀** (테이블 안 만듦) | ✅ 이해함 |
| 2 | questions | 질문 목록 (단기 5개 + 장기 3개) | ⬜ |
| 3 | question_deliveries | 누구에게 언제 어떤 질문이 나왔나 | ⬜ |
| 4 | answers | 내가 한 답변 | ⬜ |
| 5 | beads | 구슬 (하루 1개 + 특별한 구슬), 퇴사각 지수 | ⬜ |
| 6 | ghosts | 내 유령 (이름, 친밀도) | ⬜ |
| 7 | intimacy_logs | 친밀도가 언제 왜 올랐나 | ⬜ |
| 8 | settings | 메뉴 설정값 | ⬜ |

> 순서와 테이블 목록은 진행하면서 바뀔 수 있음

상태: ✅ 이해함 · 🔄 진행 중 · ⬜ 아직

## 전체 그림 (진행하면서 채움)

```
auth.users (Supabase 관리)
```
