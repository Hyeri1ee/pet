## 모든 테이블 공통 규칙

| 규칙 | 이유 |
| --- | --- |
| 기록 테이블에는 `user_id` (= `auth.users` 의 id) | 누구 것인지 + RLS ([Supabase 구조](00-supabase-구조.md)) |
| `id` 는 uuid | 겹치지 않는 번호 |
| `created_at`, 필요하면 `updated_at` | 언제 만들고 고쳤는지 |

> 데이터 저장 방식: **Supabase 만 사용** (오프라인 미지원) → [C-6](../기획정리_추가정리필요요소.md)

## 전체 그림

> 0~8번 완료. 자세한 관계도 · 칸 · 함수 목록은 **[ERD.md](ERD.md)** (그림: [ERD.png](ERD.png))

```
                        questions            (질문 8개, 모두가 같이 봄 · user_id 없음)
                            │ 1
                            ▼ N   question_id
auth.users ──1:N──▶ question_deliveries ──1:0..1──▶ answers ──N:1──▶ balls
(Supabase)  user_id  (나온 질문 한 줄)    delivery_id   (답 한 줄)  ball_id  (구슬)
   │
   ├──1:1──▶ ghosts ──1:N──▶ intimacy_logs     (유령 · 친밀도 · 친밀도 기록)
   └──1:1──▶ settings                          (메뉴 설정값)
```

- 질문 뽑기 · 답 저장 · 구슬 생성 · 친밀도 기록은 **전부 DB 함수** (조작 방지). 앱은 읽기만 하고, **유령 이름과 설정만** 직접 바꿈
- `answers` · `balls` · `question_deliveries` 에도 `user_id` 가 있음 (누구 것인지 + RLS)
