## A. 기존 문서와 다른 부분

### A-1. ✅ 하루 질문 개수 · 단기 지표 — 결정 (2026-11-18)
**결정: 단기 지표 5개, 매일 3개 랜덤**

| 평가 항목 | 설문 방식 |
| --- | --- |
| 퇴사 충동 | 사직서에 도장 찍기 |
| 업무 스트레스 | 풍선 불기 → 터뜨리기 |
| 업무량 | 서류 쌓기 (높이 m, 랜드마크 비교) |
| 감정 소모 | HP바 슬라이더 (최대 100) |
| 성취감 | 도장 3개 중 1개 (때려치워 / 이걸해냄 / 내가짱이야) |

- 질문 · 설문 방식 상세는 [기획정리.md](기획정리.md) 3. 오늘의 질문
- 남은 작업: [ERD.md](legacy/ERD.md) 의 "단기 지표 7개 · 하루 2개" → **5개 · 하루 3개**로 수정, `draw_daily_questions()` 규칙 수정
- 참고: 풀이 5개라 같은 질문이 자주 반복됨 → "최근 3일 가중치 낮춤" 규칙을 유지할지는 개발 때 확인

### A-2. ✅ 1~2개만 답했을 때 구슬 처리 — 결정 (2026-11-18)
**결정: 첫 답에 자동 생성** (구슬 색은 단색으로 정해져서 색 갱신은 없음, A-3)

- 첫 번째 답을 하면 오늘의 구슬이 바로 생기고 구슬 넣기 연출 시작
- 두 번째 · 세 번째 답은 **같은 구슬에 답변만 추가**. 하루 구슬은 1개
- "구슬 넣기" 버튼과 안내 메시지(넣기 / 더 답하기)는 **없앰** → 사용자가 따로 할 일 없음
- 남은 질문은 자정 전까지 언제든 답할 수 있음
- 배경: 1~2개일 때 선택지를 띄우는 건 부담스럽다는 리뷰 의견 (FigJam 코멘트)

남은 작은 결정 (🟡)
- 두 번째 · 세 번째 답을 했을 때 반응: 없음 / 유령 한마디 정도

### A-3. ✅ 구슬 색 — 결정 (2026-11-18)
**결정: 우선 단색.** 점수에 따라 색을 나누지 않음

- 기존 안([화면-구슬병.md](legacy/화면-구슬병.md) 연속 그라데이션)과 흐름도 안(빨강 · 노랑 · 초록 3단계)은 **보류**
- 특별한 구슬은 모양(반짝임 등)으로만 구분
- 답변 점수는 계속 저장 → 나중에 점수별 색을 넣을 때 다시 논의 (그때 경계값, 색약 대응 함께 정함)
- 남은 작업: [화면-구슬병.md](legacy/화면-구슬병.md) 의 "구슬 색 = 그날 퇴사각", "항목 클릭 → 해당 구슬만 빛나기" 등 색 관련 내용 정리
- 남은 작은 결정 (⚪): 단색의 실제 색 (유령 · 병 디자인과 맞춰 정함)

### A-4. ✅ 유리병이 늘 떠 있는지 — 결정 (2026-11-18)
**결정: 바탕화면에 늘 떠 있지 않음. 유령을 우클릭했을 때만 유령 옆에 유리병 선반이 나타남**

- 우클릭 메뉴와 함께 선반이 나타나고, 메뉴를 닫으면 함께 사라짐
- 구슬 넣기 연출 때는 지금처럼 이번 달 병이 잠깐 나타났다 사라짐
- 따로 뜨는 "선반 창"은 없음 → "모든 연출은 유령 주변에서만" 원칙과 맞음
- 우클릭 메뉴의 "기록 보기" 항목은 뺌
- 남은 작업: [화면-구슬병.md](legacy/화면-구슬병.md) 의 "병이 바탕화면에 늘 떠 있음", 병 드래그 · 흔들기, 병 위치 정하기, 병 숨기기 내용 정리

남은 작은 결정 (🟡)
- **선반이 언제 닫히는지**: 병을 눌러 구슬을 펼치거나 구슬을 눌러 답변을 보는 중에는 메뉴가 닫혀도 유지해야 함 → "선반 바깥을 클릭하면 닫힘"으로 할지
- **유령을 숨긴 상태에서 기록 보기**: 트레이 메뉴의 "기록 보기"를 누르면 유령이 잠깐 나타나면서 선반을 보여줄지, 트레이 아이콘 근처에 선반을 띄울지
- 유령이 화면 가장자리에 있을 때 선반이 나오는 방향 (왼쪽 / 오른쪽 / 위)
- 펼친 구슬(한 달 31개)과 답변 상세를 유령 옆 좁은 공간에 어떻게 배치할지

### A-5. 🔴 친밀도 — 요인 확정 (2026-11-18), 점수 규칙 정리 필요
**결정: 친밀도가 오르는 요인 3가지**

| # | 요인 | 기준 |
| --- | --- | --- |
| 1 | 유령 쓰다듬기 | 쓰다듬은 횟수 |
| 2 | 질문 답변 | **답변할 때마다** 오름 (2026-11-21 변경: 처음엔 하루 단위로 답했는지만 봤음). 단기 · 장기 모두 해당 |
| 3 | 유령이 나타나 있던 시간 | 데스크톱에 유령이 떠 있던 시간 |

| 기존 ([ERD.md](legacy/ERD.md)) | 변경 |
| --- | --- |
| **레벨 · 경험치**(기록량) + **애정도**(쓰다듬기) 두 축 | **친밀도** 하나, 5단계 |

ERD 에 임시로 반영한 것 (2026-11-21)
- 점수 · 단계는 [`ghosts`](erd/06-ghosts.md) 에 저장: `intimacy_score`(줄지 않음) + `stage`(1~5, 점수로 자동 계산)
- 오른 기록은 [`intimacy_logs`](erd/07-intimacy-logs.md) 에 한 줄씩 쌓음 (쓰다듬기 1번 · 질문 답변 1번 · 나타나 있던 분 = 각각 1줄)
- 단계 경계는 임시로 **100점마다 1단계** (`intimacy_stage` 함수). 값이 정해지면 함수만 고침

정할 것
- 요인별 점수 (예: 쓰다듬기 1번 +1, 질문 답변 1번 +5, 나타나 있던 1시간 +2)
- ~~하루 상한값과 요인별 상한~~ → **두지 않기로 결정 (2026-11-21)**. 대신 쓰다듬기 연타 · 켜두기로 점수가 부풀 수 있어 요인별 점수를 작게 잡거나 최소 간격을 둘지 정해야 함
- 질문 답변 점수: 단기와 장기를 **같게** 줄지 (이달의 질문 답은 더 줄지)
- 나타나 있던 시간: **숨김 상태 · 졸기 상태**도 포함할지, 컴퓨터를 안 쓰는 시간(자리 비움)은 뺄지
- **단계가 올라가는 규칙** (친밀도 점수 → 5단계): "몇 점이면 몇 단계"를 정한 표가 필요함
  - 예(안): **1단계에서 2단계로 올라가려면 친밀도 100점** 처럼 단계마다 필요 점수를 정함
  - 매 단계 같은 점수씩(균등, 예: 100점마다 한 단계) vs 뒤로 갈수록 더 많이 필요(곡선)
  - 처음 시작(0점)이 1단계인지
  - **상한이 없으므로 단계가 오르는 속도는 요인별 점수가 정함**: 하루에 보통 얼마나 쌓이는지(답변 최대 3~4번, 켜 둔 시간, 쓰다듬기) 추정해서 단계 하나에 며칠이 걸리는지, 5단계까지 총 며칠인지 계산해 정함
  - 이 규칙이 정해지면 DB 의 `intimacy_stage(score)` 함수에 들어가고, `ghosts.stage` 칸이 이 함수로 채워짐 ([06-ghosts.md](erd/06-ghosts.md))
- 단계별로 열리는 대사 · 행동 목록
- ~~기존 레벨 · 경험치 · 애정도를 친밀도 하나로 합칠지~~ → **합침** (새 ERD: `ghosts.intimacy_score` · `stage`. 레벨 · 경험치 · 애정도 칸은 없음)
- 참고: 기존 `exp_events`(경험치 장부) 구조를 친밀도 장부로 가져옴 → [`intimacy_logs`](erd/07-intimacy-logs.md) (`source`: `stroke` 쓰다듬기 / `answer` 질문 답변 / `presence` 나타난 시간)

### A-6. ✅ 장기 질문 주기 — 결정 (2026-11-21)
**결정: 한 달에 한 번.** 분기별이 아니라 **월 1회**, 매달 3개 중 1개를 골라 답함 (3주에 한 번 안도 검토했으나 월 1회로 확정)

| 기존 ([ERD.md](legacy/ERD.md)) | 확정 |
| --- | --- |
| 장기 지표 **8개**, 월 · 분기 질문 | 장기 지표 **3개**, **월 1회** (3개 중 1개 선택) |

- "분기별 측정과 월 1회 이벤트를 맞추는" 문제(안 1~3)는 **월 1회로 정해서 없어짐**: 매달 3개가 모두 나오고 그중 1개를 고름. 지표별 이월 없음
- **그날 답하지 않으면 그 달은 없음**: 이달의 질문도 오늘의 질문처럼 **나온 날 자정에 만료** ([question_deliveries](erd/03-question-deliveries.md))
- 오늘의 구슬과 **별개**로 특별한 구슬 1개가 생김 (한 달에 1개)
- [기획정리.md](기획정리.md) 4 의 장기 질문 표 주기도 "분기별" → **"월 1회"** 로 고침

남은 확인 (🟡)
- "정해진 날"이 **매달 며칠**인지 (매월 1일 / 마지막 금요일 / 사용자별 다름) → [D-1](#d-erd-작업-중-새로-생긴-확인-사항)
- 그날 **오늘의 질문도 같이 나오는지** → D-2
- 남은 작업: [ERD.md](legacy/ERD.md) 의 "장기 지표 8개" → 새 ERD 에서는 3개로 반영됨 ([questions](erd/02-questions.md))

### A-9. 🔴 답변 → 점수(0~100) 변환 규칙
설문 방식이 정해졌으니, 각 답변을 [ERD.md](legacy/ERD.md) 규칙대로 **0~100점 (높을수록 퇴사각↑)** 으로 바꾸는 기준이 필요함

| 지표 | 답변 형태 | 정할 것 |
| --- | --- | --- |
| 퇴사 충동 | 도장 횟수 | **최대 횟수** (예: 10번 = 100점), 0번 허용 여부 |
| 업무 스트레스 | 풍선 크기 | 크기 단계 (연속값 / n단계), 최대 크기 |
| 업무량 | 서류 높이 | **최대 높이**와 점수 매핑. 랜드마크 목록 (예: 책상 → 사람 키 → 롯데타워) |
| 감정 소모 | HP 0~100 | HP가 **줄어들수록** 지친 것 → `100 - HP` 로 뒤집는지 확인 |
| 성취감 | 3개 중 1개 | 3단계 점수 (예: 때려치워 100 / 이걸해냄 50 / 내가짱이야 0). 긍정 지표라 뒤집기 |
| 복지 | 3개 중 1개 | 쓸모 있음 / 그럭저럭 / 귀중품 점수. 긍정 지표 |
| 조직문화 | 3개 중 1개 | 편한 자세 / 그냥 앉아 있는 자세 / 군기 들어있는 자세 점수 |
| 고용 · 사업 안정성 | 3개 중 1개 | 맑음 / 구름 / 폭풍 점수 |

- 확인: 업무량 질문은 "감당할 수 있는 수준이었나요?" (긍정 문장)인데 답변은 "느낀 업무량만큼 쌓기" (많을수록 나쁨) → 질문 문구와 답변 방향을 맞출지
- 확인: 3지선다(성취감 · 장기 지표)는 점수 간격이 커서 날마다 점수가 크게 흔들림 → 괜찮은지
- 참고: 구슬 색은 우선 단색(A-3)이지만, 나중에 점수별 색을 넣으려면 이 규칙이 기준이 됨

ERD 에 반영한 것 (2026-11-21)
- 답은 [`answers`](erd/04-answers.md) 에 **원본(`raw_value`, 문자열)** 과 **점수(`score`, 0~100)** 를 같이 저장 (규칙이 바뀌어도 원본으로 다시 계산)
- 긍정 지표(성취감 · 복지 등)는 [`questions.direction`](erd/02-questions.md) 이 `positive` → 점수를 뒤집어 저장
- 점수 계산은 앱이 아니라 **DB 함수(`submit_answer`) 안에서** (조작 방지). 최대 횟수 · 선택지별 점수는 `questions.config` 에 넣을 자리가 있음
- **남은 것은 위 표의 값들**(최대 도장 횟수, 풍선 단계, 서류 높이 매핑, 선택지 점수)

### A-10. 🔴 퇴사각 지수 계산 방식
구슬을 누르면 보이는 숫자를 어떻게 계산할지

- 기존 ([ERD.md](legacy/ERD.md)): 단기 점수(최근 7일) × 0.6 + 장기 점수(월 · 분기) × 0.4 = 종합 점수
- 정할 것
  - **그날 답한 단기 질문의 평균**만 쓸지 (단순, 날마다 독립적) vs 기존처럼 최근 7일 · 장기 점수를 섞을지
  - 특별한 구슬(이달의 질문)의 숫자: 그 답변 1개의 점수만 보여줄지
  - 답이 1개뿐인 날도 그대로 보여줄지 (질문마다 점수 기준이 달라 날짜끼리 비교가 어려움)
- 답변 → 점수 변환(A-9)이 먼저 정해져야 함

ERD 에 임시로 반영한 것 (2026-11-21): [`balls.score`](erd/05-balls.md) = **그날 답한 단기 질문의 점수 평균** (답 1개면 그 점수), 특별한 구슬은 **그 답 1개의 점수**. 구슬에 저장해 두므로 계산식이 바뀌면 함수만 고치면 됨

### C-6. ✅ 데이터 저장 방식 — 결정 (2026-11-18)
**결정: Supabase 만 사용.** Supabase 가 데이터 원본이고, **설정값도 Supabase 에 저장함 (PC 에는 저장하지 않음, 2026-11-21 갱신)**. **오프라인은 지원하지 않음**

```
[PC]  유령 앱 ── 인터넷 ──→  Supabase (원본, 서울)  ←── [나중에] 관리자 웹
```

검토 과정
- 오프라인 지원(PC DB + Supabase 동기화)도 검토함
- 하지만 데이터가 두 곳에 있어서 생기는 문제가 많음: 동기화 로직, 충돌, PC 시계 조작, 점수 계산 로직 두 벌, DB 구조 두 벌, PC 2대에서 하루 구슬 2개, 동기화 전 삭제 시 기록 손실 등
- 1인 개발 · MVP 단계에서는 부담이 커서 **Supabase 만 쓰기로 함**. 필요하면 나중에 확장 (테이블 구조는 거의 그대로 쓸 수 있음)

이렇게 정하면
- 답변 · 구슬 · 친밀도는 바로 Supabase 에 저장
- 질문 뽑기 · 점수 계산은 **DB 함수 · 트리거(서버)** 에서 처리 → 계산 로직 한 곳, 조작 방지
- **설정값도 Supabase 에 저장** (앱이 켜질 때 읽어서 적용). PC 에는 따로 저장하지 않음

정할 것 (🟡)
- **인터넷이 끊겼을 때 유령의 동작**: 유령은 계속 떠 있고 돌아다니되, 질문 · 기록 보기는 "연결이 끊겼어" 말풍선으로 안내? 질문 아이콘은 숨김?
- 답변 도중 연결이 끊기면: 다시 연결될 때 재시도 / 실패 안내
- 설정도 Supabase 에만 있어서, 앱을 켤 때 연결이 없으면 **설정을 어떻게 적용할지**(기본값으로 뜨는지 등)
